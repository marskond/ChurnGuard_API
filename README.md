# 🛡️ ChurnGuard API: Reliable ML Delivery

Простой, но идеально упакованный ML-сервис для прогнозирования оттока клиентов. Проект демонстрирует не столько сложность самой модели, сколько **инженерные практики доставки ML-решений в продакшн**.

> 💡 **Моя цель как инженера:** Меня привлекает стык дисциплин (Analytics + DevOps + ML). Я стремлюсь быть тем специалистом, который переводит идеи Data Scientist-ов в стабильно работающие продакшн-решения, гарантируя их надежность, масштабируемость и наблюдаемость.

---

## 🏗 Архитектура и MLOps-практики

Этот проект реализует ключевые принципы надежной доставки ML-моделей:

1. **Контракты данных (Data Contracts):** Использование `Pydantic` для строгой валидации входных данных. Модель защищена от "мусора" на входе (возвращает `422 Unprocessable Entity` вместо падения).
2. **Контейнеризация (Docker):** Воспроизводимая среда выполнения. Приложение упаковано в оптимизированный образ (`python:slim`), гарантирующий одинаковое поведение на любой машине.
3. **CI/CD (GitHub Actions):** Автоматическая проверка кода при каждом push. Пайплайн включает линтинг (`flake8`) и автоматические тесты (`pytest`), защищающие основную ветку от регрессий.
4. **Наблюдаемость (Observability):** 
   - Структурированное логирование всех запросов и ошибок.
   - Интеграция с **Prometheus** (`/metrics`) для мониторинга RPS, латентности и состояния приложения (Health/Ready checks).

## 🚀 Быстрый старт

### Вариант А: Локальный запуск (для разработки)
```bash
# 1. Клонировать репозиторий и создать окружение
git clone https://github.com/marskond/ChurnGuard_API.git
cd ChurnGuard_API
python3 -m venv venv
source venv/bin/activate  # Для Windows: venv\Scripts\activate

# 2. Установить зависимости и обучить модель

# Одна команда для сборки и запуска всего стека
docker-compose up --build


## 📊 Нагрузочное тестирование (Load Testing & QA)

Проект включает в себя комплексную проверку надежности:
1. **Unit-тесты (`pytest`)**: Автоматическая проверка контрактов данных (валидация Pydantic) и структуры ответов модели.
2. **Нагрузочное тестирование (`Locust`)**: Сценарий имитирует поведение реальных пользователей, проверяя стабильность API под нагрузкой.
